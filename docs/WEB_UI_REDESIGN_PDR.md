# Web 管理端重设计 · PDR（产品设计需求文档）

- 项目：cosDnaPorxy DNS 代理 · Web 配置中心（`internal/web/admin.html`，内嵌单文件）
- 日期：2026-09-23
- 状态：**待用户确认**，确认后进入开发
- 边界：本轮只重做前端页面（HTML/CSS/JS）。**后端 API、配置存储、DNS 逻辑零改动**

---

## 1. 背景与问题定性

用户反馈："现在太难使用了"。

对现有页面（已对照源码与运行截图审计）的结论：**不是视觉丑的问题，而是信息架构与交互流程问题**。把 28 项配置平铺成一张超长表单，高频与低频操作权重相同，缺少状态反馈与任务边界，用户无法快速完成"改一项→确认生效"的闭环。

### 1.1 现状审计（按严重度排序）

| # | 问题 | 证据 | 严重度 |
|---|------|------|--------|
| P1 | **28 个字段一张长表单**，6 个 fieldset 纵向堆叠，首屏只能看到 2 组，修改下方字段需长距离滚动与定位 | 基本配置页截图，页高约 5 屏 | 高 |
| P2 | **底部固定"保存配置"栏在所有页面常驻**，包括"域名篡改"页——但该页规则有独立保存按钮，全局按钮与当前任务无关，造成"我改的规则到底哪个按钮生效"的困惑 | admin.html `.bar` fixed 定位 | 高 |
| P3 | **篡改规则的编辑入口与表单分离**：点表格里的"编辑"后，表单在页面最下方填充，页面不滚动、无提示，用户看不到已进入编辑态 | `editOverride()` 仅填值，无滚动/高亮 | 高 |
| P4 | **无变更感知**：改了哪些字段、有没有未保存修改，完全无提示；刷新/离开页面可能丢失修改且无拦截 | 无 dirty 追踪 | 高 |
| P5 | **"需重启"语义弱**：仅字段名旁一行橙色小字；保存后才在左下角出现一句提示，无法在改之前预知"这项不会立即生效" | legend/label 内 `.rr` 徽章 | 中 |
| P6 | **时长值直接暴露 Go 原始格式**：界面显示 `30m0s`、`24h0m0s`、`96h0m0s`，对人类不友好 | 截图实见；后端 `Duration.String()` | 中 |
| P7 | **无客户端校验**：端口范围、时长格式、A/AAAA 记录值是否合法 IP，都要提交后等服务器报错；错误也只显示在左下角小字 | `saveConfig/saveOverride` 无前置校验 | 中 |
| P8 | **规则列表无搜索/筛选/启停快捷操作**：规则增多后无法快速定位；停用一条规则必须进编辑表单 | tab-ovr 仅原生 table | 中 |
| P9 | **视觉权重无层级**：数据文件路径等一年改不了一次的字段，与上游 DNS、开关等高频字段外观完全一致；整页只有一种输入框样式 | 全部 fieldset 同构 | 中 |
| P10 | 反馈区域固定在屏幕左下角、小字、无自动消失；成功/失败信息一闪或长期滞留都无管理 | `#msg` | 低 |
| P11 | 删除规则用浏览器原生 `confirm()`，视觉与产品脱节；无"新增规则"空状态引导 | `delOverride()` | 低 |

### 1.2 现有资产（保留，不推倒）

- API 契约稳定：`GET/PUT /api/config`、`GET/POST /api/overrides`、`PUT/DELETE /api/overrides/{id}`，`PUT /api/config` 返回 `restart_required`。
- E2E 脚本（`scripts/test_web_config.sh`，25 项）与 Go 单测只打 JSON API，**不依赖 HTML 结构**，页面重做不影响测试。
- 服务端校验规则（端口 1–65535、上游非空、A=IPv4/AAAA=IPv6/CNAME=域名）前端对齐即可。

## 2. 用户与任务

单一用户画像：**在本机/内网自托管 DNS 代理的进阶用户**，熟悉 DNS 概念，用浏览器偶尔但明确地完成管理任务。

任务频率分级（决定信息层级）：

- **高频**（每周可能动）：增删改篡改规则、停/启规则、改上游 DNS、调日志级别排障
- **中频**（装机/调优时动）：缓存 TTL、超时、云替换开关与替换域名、分流开关与国内 DNS
- **低频**（基本只在初始化时动）：监听端口、Web 地址、数据文件路径/URL/刷新间隔、日志格式、缓存容量/线程数

设计含义：高频任务 1 次点击到达；低频字段收进分区末位/折叠区，不抢注意力。

## 3. 设计目标与原则

| 目标 | 衡量标准（验收用） |
|------|------|
| 任务可达 | 任意高频任务：进入页面后 ≤1 次点击 + 无需滚动即可开始操作 |
| 状态可知 | 任何时刻用户能回答三个问题：我改了什么？保存了吗？需要重启吗？ |
| 错误前置 | 格式类错误 100% 在提交前端拦截，并定位到具体字段 |
| 结构可生长 | 未来新增一个配置分区，只需加一组 section 元数据，不改外壳 |
| 零依赖可部署 | 仍是单个 `admin.html`，原生 HTML/CSS/JS，无 npm/构建步骤，`go:embed` 方式不变 |

设计原则：

1. **按任务分组，不按代码结构分组**（分区命名用用户语言：上游 / 分流 / 云替换，而不是字段堆砌）。
2. **渐进披露**：常用字段露在外面，低频字段折叠为"高级设置"。
3. **就地反馈**：校验错误在字段下方；保存结果在右上角 Toast；需重启用顶部横幅。
4. **危险操作可撤销感**：删除要二次确认（产品化弹窗，非原生 confirm），规则删除后提供 5 秒"撤销"。
5. **克制**：不加后端不支持数据的"仪表盘假数据"，不加未被要求的功能。

## 4. 信息架构（IA）——三选一，推荐方案 A

### 方案 A：左侧固定导航 + 分区页面（推荐）

```
┌────────────────────────────────────────────────────────────┐
│ 顶栏: DNS 代理配置中心      [● 有未保存更改]  [保存并应用]  │
├──────────────┬─────────────────────────────────────────────┤
│  设置        │                                             │
│   · 常规服务 │           当前分区内容（单栏/双栏卡片）       │
│   · 上游与分流│                                             │
│   · 云 IP 替换│                                             │
│   · 缓存与高级│                                             │
│              │                                             │
│  规则        │                                             │
│   · 域名篡改  │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

- 28 个配置字段拆进 4 个分区（见 §5.1），每屏只面对 1 个主题、6–10 个字段。
- 左侧导航始终可见位置感；hash 路由（`#/settings/upstream`）支持刷新与前进后退。
- 域名篡改为独立全宽页面，规则列表为主角。
- 优点：层级清晰、扩展性好、符合运维后台心智。缺点：从"滚动一页"变为"点击切换"，一次性通览全部配置不再直接——但可在"缓存与高级"底部提供"展开全部"（低成本折中）。

### 方案 B：保留顶部两个 Tab，基本配置改为"右侧锚点目录 + 单页滚动"

改动最小，但 P1（长表单）只是缓解没有解决，规则页与设置页的形态差异依然别扭。**不推荐**，仅作为求稳备选。

### 方案 C：方案 A + 概览仪表盘

在 A 基础上增加首页状态卡（运行端口、缓存命中率、QPS、规则数）。**当前后端没有任何统计 API，做了就是假数据**；若要做需另行排期后端开发。本轮不做。

## 5. 页面布局详稿

### 5.0 全局外壳

- **顶栏（56px）**：左侧产品名 + 当前 DNS 监听地址（如 `:53`）；右侧状态区：
  - 无改动：灰色"所有更改已保存"
  - 有改动：琥珀色圆点 + "有未保存更改" + 主按钮"保存并应用"
  - 保存返回 `restart_required=true`：顶栏下方出现**黄色横幅**"以下更改需重启进程后生效：监听端口、…"，可关闭（关闭=已知晓，不改变事实）。
- **侧栏（200px，折叠到图标 56px）**：分区名称 + 未保存小圆点（哪个分区有改动一眼可见）。
- **内容区最大宽 960px**，避免超宽屏下表单拉得过长。
- 移动端（<768px）侧栏变为顶部抽屉，汉堡按钮呼出；表单自动单栏。

### 5.1 设置类分区（4 个）

字段归属（全部现有字段，不增不减）：

**① 常规服务**
- 日志级别（select，热更新）
- 监听端口（数字，需重启）、Web 管理端地址（文本，需重启）、日志格式（select，需重启）→ 收进该页底部"高级/需重启"折叠区

**② 上游与分流**
- 上游 DNS 服务器（多行→改为"条目列表"组件：每行一个输入框 + 删除图标，"+ 添加上游"按钮；按 scheme 自动显示协议徽标 udp/tcp/https/tls/h3）
- 传统协议超时、现代协议超时（时长输入，带单位快捷辅助）
- 备用 DNS
- 卡片"中国域名分流"：右上角开关；开启后展开 定向域名默认 DNS、中国域名 DNS；其数据来源（定向域名 文件/URL/刷新间隔、中国域名 文件/URL/刷新间隔）收入该卡片内"数据源（高级，改动需重启）"折叠

**③ 云 IP 检测与替换**
- 两张开关卡并列：Cloudflare 检测替换 / AWS 检测替换（开关关闭时，该卡片下替换域名等字段禁用置灰）
- CF 替换域名、AWS 替换域名、云替换响应缓存时间、替换域名最大 IP 数、CNAME 链收集深度
- IP 段数据文件（v4/v6/AWS）与刷新间隔 → 折叠"数据文件（需重启）"

**④ 缓存与高级**
- 兜底缓存 TTL（热更新）
- 最大缓存条目数、异步刷新线程数（需重启）置于"高级（需重启）"折叠
- 页尾提供"展开全部配置（单页视图）"文字入口，满足一次性通览

每个分区视觉结构：

```
分区标题 + 一句话说明
┌─ 卡片 ────────────────────────────────┐
│ 字段标签              [需重启]  ?帮助  │
│ [输入框]                             │
│ 帮助/错误文字                         │
│                                      │
│ 字段标签                              │
│ [输入框]                             │
└──────────────────────────────────────┘
[放弃更改]              [保存并应用]
```

- 双栏栅格仅用于语义成对的短字段（如两个超时、文件 v4/v6），窄屏降单栏；长文本（URL/域名/上游）始终整行。
- "需重启"字段统一用描边徽章；标签旁 `?` 悬停显示该字段作用（文案取自代码注释原意，不杜撰）。

### 5.2 域名篡改页（独立全宽）

```
域名篡改规则                         [+ 新增规则]
命中规则直接返回本地构造响应，优先级高于缓存与所有上游。
[搜索域名或记录值........] [类型: 全部▾] [状态: 全部▾]
┌────────────────────────────────────────────────────────┐
│ 开关 │ 域名                │ 类型 │ 记录值      │ TTL │ 操作│
│  ●  │ www.baidu.com       │ A    │ 127.0.0.1  │ 1   │ ⋯  │
│  ○  │ .example.com        │ CNAME│ target.com  │ 60  │ ⋯  │
└────────────────────────────────────────────────────────┘
空状态：插画位 + "还没有规则，新增第一条 →"
```

- **列表**：开关列是即时生效的 Switch（调用 PUT，失败回滚并 Toast 报错）；类型彩色徽章（A 蓝 / AAAA 紫 / CNAME 青）；域名用等宽字体；操作列"编辑 / 删除"。
- **新增/编辑 → 右侧抽屉（Drawer）**，从右侧滑入，半屏宽：
  - 域名（实时提示匹配模式：输入 `a.com` 显示"精确匹配"；`.a.com`/`*.a.com` 显示"后缀匹配"）
  - 记录类型（分段选择器 A / AAAA / CNAME，切换后记录值输入框的占位与校验规则同步切换）
  - 记录值（失焦即校验：A 必须 IPv4、AAAA 必须 IPv6、CNAME 必须域名）
  - TTL（数字，默认 60）、启用开关
  - 底部：取消 / 保存规则。编辑态标题"编辑规则 #5"，保存按钮文案"保存修改"。
  - Esc 关闭、有未保存修改时二次确认、焦点陷阱。
- **删除**：产品化确认弹窗（规则域名 + 类型明示）；删除成功后右下角 Toast"规则已删除 [撤销]"，5 秒内撤销=按原数据 POST 重建。
- 搜索/筛选纯前端即时过滤；结果数提示。

## 6. 视觉设计系统（Design Tokens）

延续现有暗色基调（运维工具在深色环境下舒适），做体系化收敛，而非换风格：

**色彩（暗色，CSS 变量）**

| token | 值（示意） | 用途 |
|------|-----------|------|
| `--bg-app` | `#0d1117` | 页面底 |
| `--bg-surface` | `#161b22` | 卡片/侧栏 |
| `--bg-inset` | `#0b0f14` | 输入框底 |
| `--border` | `#2a313c` | 描边 |
| `--text-1` | `#e6edf3` | 主文字 |
| `--text-2` | `#9aa7b4` | 次要文字/标签 |
| `--text-3` | `#6b7681` | 占位/禁用 |
| `--accent` | `#4da3ff` | 主按钮/焦点/链接 |
| `--success` | `#3fb950` | 成功/A 徽章 |
| `--warning` | `#e0a53c` | 需重启/脏状态 |
| `--danger` | `#f85149` | 删除/错误 |
| `--info` | `#bc8cff` | AAAA 徽章等辅助 |

**字体**：系统栈 `-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`；数字/域名/IP/路径用 `ui-monospace, Menlo, monospace`。基准 13px（密集运维密度），标题 15/17px，行高 1.55。

**间距**：4 的倍数（4/8/12/16/24/32）；卡片内边距 16–20；字段纵向间距 16；卡片间距 16。

**圆角**：控件 6px、卡片 8px、徽章 10px（与现状衔接）。

**组件状态**：输入框默认/悬停/聚焦（2px accent 半透明外环）/错误（红边+红字）/禁用（降透明度 40%）；按钮 primary/ghost/danger 三态 + loading 态（保存中转圈禁用，防重复提交）。

**动效**：仅 120–180ms 的透明度/位移过渡（抽屉滑入 200ms），无装饰动画；尊重 `prefers-reduced-motion`。

**时长人性化**：加载配置后前端把 Go 时长转成人读形式（`30m0s→30m`、`24h0m0s→24h`、`96h0m0s→96h`、`1500ms 显示 1.5s`）；保存时仍提交合法 Go duration 字符串（原样或归一化后均可，后端解析不变）。输入框下方给格式提示 `如 1.5s / 30m / 24h`，失焦校验。

## 7. 关键交互规范

1. **脏状态追踪**：加载时存基线快照；任一控件变更即标记该字段与所属分区（侧栏圆点 + 顶栏状态 + 分区底栏按钮亮起）。保存成功后重新基线化。`beforeunload` 与路由切换在有脏数据时拦截确认。
2. **分区保存**：每个设置分区底部"保存并应用 / 放弃更改"，只提交该分区字段（合并进完整 ConfigJSON 后 PUT，后端接口不变）。顶栏保存按钮=提交当前分区。**彻底移除在规则页出现的全局保存栏**。
3. **保存反馈**：按钮 loading → 成功 Toast"已保存并热更新生效"；`restart_required=true` 时成功 Toast 文案为"已保存，部分更改需重启生效"并升起黄色横幅列出字段；失败时 Toast + 首个错误字段聚焦并在字段下红字说明。
4. **前端校验**（与 `ValidateConfig`/`validateOverride` 对齐）：端口 1–65535；上游至少 1 条且 scheme 合法（udp/tcp/https/tls/h3）；时长正则 `^\d+(\.\d+)?(ms|s|m|h)$`；A=IPv4、AAAA=IPv6、CNAME 非空无空格；TTL 正整数。错误不阻塞相邻字段编辑。
5. **开关联动**：云替换两个总开关关闭时，其子字段禁用；中国域名分流关闭时 DNS/数据源字段禁用。禁用值提交时仍原样带回（不丢配置）。
6. **即时生效类操作**：规则 Switch 启停、Drawer 保存，走 overrides API 后即时刷新列表，不经"保存配置"。

## 8. 响应式与可访问性

- 断点：≥1024 双栏卡片；<768 单栏 + 侧栏抽屉；表格在窄屏改为卡片式行（域名/类型/值堆叠）。
- 可访问性：所有控件有 label（`for/id`）；Switch 用 `role="switch" aria-checked`；抽屉焦点陷阱 + Esc + 焦点归还；色彩不作为唯一信息载体（状态同时有文案/图标）；对比度 ≥ WCAG AA；键盘 Tab 顺序符合视觉顺序。

## 9. 技术方案与实施边界

- **唯一改动文件**：`internal/web/admin.html`（重写，仍是一个自包含文件，原生 JS，无外部依赖/无 CDN/无构建）。
- **不改**：`server.go`、`config` 包、API 路径与字段名、`go:embed` 机制。
- JS 组织为轻量模块函数：`api()` 封装保留；新增 状态存储（基线快照/dirty 集合）、路由（hash）、分区 schema 驱动渲染（字段元数据数组：id/标签/类型/分区/是否需重启/帮助文案/校验器），避免 28 个字段各写一遍事件。
- 总代码量控制在单文件 ~700–900 行，不引入框架。

### 实施阶段（每阶段独立可验证、可回退）

1. **阶段 1 · 外壳与设计系统**：侧栏+顶栏+tokens+卡片/输入/按钮/Toast 组件，先接"常规服务"一个分区跑通 dirty→校验→保存→重启横幅全链路。
