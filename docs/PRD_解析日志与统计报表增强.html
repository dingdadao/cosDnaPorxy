Product Requirements Document

解析日志与统计报表增强（含外网访问筛选）

面向 cosDnaPorxy 本地代理 DNS 服务的管理端可观测能力：让每一次解析「谁在用、从哪来、走哪条路、结果如何」都能被辨识、筛选与聚合。

版本 v1 状态 评审中 日期 2026-10-13 范围 管理端 · 解析日志 / 统计报表
主要使用者
运维 / 值班人员（管理端使用者）
触发时机
收到「某网络环境下解析异常 / 某来源流量异常」的反馈，需要定位并复盘
核心任务
按来源（外网/内网、协议、客户端 IP）筛出目标请求，看清其路径、结果与耗时分布

1背景与问题

管理端已提供 解析日志（逐条记录每次查询走的路径、命中的分流列表与上游、最终应答与耗时）与 统计报表（在日志保留期内按来源路径、分流列表、Top 域名、按天趋势、rcode / qtype 等维度聚合）。但在实际排障中，「谁在用」这一维度缺失，导致以下几类问题反复出现：

问题 1：客户端地址没有「来源」语义，外网与内网流量混在一起

日志里的「客户端」列存在两种形态：经公网加密入口接入的请求记录的是由前置代理透传的真实客户端 IP（纯 IP，无端口）；内网直连的请求记录的是连接对端地址（含端口）。同一列里既有公网 IP 又有带端口的内网地址，无法直接区分这条记录究竟来自外网入口还是内网直连，也无法据此筛选。

问题 2：缺少来源相关的筛选维度

当前日志页仅支持「域名关键字 / 来源路径 / 类型 / 时间区间」筛选，客户端地址只能靠关键字模糊搜索，不能按「外网/内网」「接入协议」「客户端 IP 或网段」精确筛选。排障时无法快速把某一来源的流量单独拎出来。

问题 3：统计报表缺少「谁在用」的分布

现有聚合围绕「走了哪条路」与「查了什么域名」，但没有来源类型占比、接入协议占比、Top 客户端来源等维度，无法回答「外网与内网各占多少」「哪个客户端查询量最大」这类问题。

产品决策

为解析日志补齐统一的「来源维度」（客户端来源类型、接入协议、接入方式、归一化客户端 IP），并把同一组来源条件同时用于日志筛选与统计聚合；新增「外网访问」快捷筛选，让外网（公网客户端）流量一键聚焦。

预期可观测结果

在一个页面上即可筛出「外网（公网客户端）请求」或「内网直连请求」，并看到其占比、平均耗时与结果分布；同一组条件在日志页与统计页给出语义一致的结果。

3范围

本 PRD 覆盖一次完整的排障旅程：从「收到某来源解析异常的反馈」到「在管理端筛出该来源的日志与统计并得出结论」。

P0 · 进入并完成任务的必要能力

  • P0 解析日志：记录并展示「来源类型 / 接入协议 / 接入方式 / 归一化客户端 IP」；筛选栏新增对应条件，保留现有筛选与分页能力。
  • P0 统计报表：新增「来源与协议」分区（来源类型占比、接入协议占比、接入方式占比、Top 客户端来源），沿用现有全部聚合。
  • P0 外网访问筛选：日志页与统计页共享同一组来源筛选条件，「外网访问」可一键聚焦外网（公网客户端）流量。
  • P0 恢复路径：无匹配 / 日志关闭 / 旧数据无来源维度时的空状态与兜底归类（见 §6）。

P1 · 支撑性增强（本期纳入）

  • P1 客户端 IP 归属标注（运营商 / 地域）：在来源分布与 Top 客户端来源中作为附注信息展示（已确认纳入本期）。

明确不做（避免范围蔓延）

  • 不做 不改动 X-Forwarded-For 的解析语义与伪造防护逻辑（已由使用者明确不处理）。
  • 不做 不新增分流引擎、不改动解析路径本身；来源维度仅用于观测与筛选，不影响解析结果。
  • 不做 不做污染检测 / 异常判定与回退（属「DoH 抗污染与可观测」另一份 PRD 的范围）。

4来源维度定义（共享口径）

以下定义是日志筛选与统计聚合唯一的依据；两处必须使用同一口径，否则结论会互相矛盾。

维度取值含义与判定
来源类型
source_kind		 外网 outer
内网 inner
未知 unknown		 按客户端 IP 的性质判定：
外网＝客户端 IP 为公网地址；
内网＝客户端 IP 命中内网网段 10.0.0.0/24；
未知＝客户端 IP 缺失或无法解析。
接入协议
protocol		 UDP TCP DoT DoH DoH3 请求到达本服务所用的传输方式。此为新增维度，用于回答「各协议各承载了多少流量」。
接入方式
via		 经代理 proxy
直连 direct		 经代理＝客户端 IP 取自前置代理透传的请求头（即经公网加密入口接入）；
直连＝客户端 IP 取自连接对端地址或静态映射。
客户端 IP
client		 归一化 IP 统一只保留 IP 主机部分：经代理的公网 IP 原样（无端口）；直连地址剥离端口后取主机。端口不再作为独立筛选维度，也不与 IP 混列。
判定优先级 · 已确认

「来源类型」按客户端 IP 是否为公网地址判定，「接入方式」按该 IP 的解析来源（请求头 vs 连接对端）判定，两者独立取值。因此一个公网客户端通过 DoT 直连打进来时，会呈现为「外网 + 直连」。内网判定网段固定为 10.0.0.0/24。

5功能需求

本节为主体。三个模块共享 §4 的来源口径与 §6 的统一规则，正文不再重复定义。

FR-1解析日志增强

目的：让每条解析记录都能被辨识「从哪来」，并能按来源精确筛选。

布局：沿用现有解析日志页——顶部筛选栏 + 下方表格 + 分页。筛选栏在原有「搜索 / 来源路径 / 类型 / 开始时间 / 结束时间 / 重置 / 刷新」基础上，新增「来源类型 / 接入协议 / 接入方式 / 客户端 IP」四组控件，并提供「外网访问」快捷按钮（见 FR-3）。表格列在原有「时间 / 域名 / 类型 / 来源 / 分流策略 / 结果 / 上游 / 耗时 / 客户端」基础上，新增来源类型、协议、接入方式的展示（可与「客户端」列合并为「来源」信息块，见下方 Demo）。

触发：打开解析日志页即按默认条件加载；修改任一筛选条件后即时刷新表格（关键字类输入做防抖，仅重绘表格以保持输入焦点）。

处理规则：

  • 写入日志时计算并保存该记录的来源类型、接入协议、接入方式与归一化客户端 IP；这些字段随记录一起进入保留策略。
  • 筛选条件之间为 AND 组合，分页沿用现有「每页条数 + 页码」机制，默认每页 50 条。
  • 客户端 IP 筛选支持精确 IP与 CIDR 网段；输入非法时前端提示，不发起查询。
  • 表格中的客户端 IP 一律为归一化 IP（不带端口）。

结果与状态变化：命中记录按时间倒序分页展示；底部计数说明显示「本次筛选 × 条」，与库内累计写入、队列溢出丢弃、保留策略等信息一并呈现（沿用现状）。

字段：

例外：

  • 客户端 IP 缺失 → 该记录来源类型记为「未知」，可被单独筛出。
  • 保留期内的旧数据没有来源维度 → 一律归入「未知」，且不参与「外网访问」快捷筛选，避免误判为外网流量。
  • 无匹配结果 → 空状态提示「没有匹配的日志」，并给出「调整关键词、来源或时间区间」的建议（沿用现状语气）。
  • 日志记录被关闭 → 页面显示「记录已关闭」提示，表格为空。

FR-2统计报表增强

目的：补齐「谁在用」的分布，让报表能回答来源与协议的构成。

布局：沿用现有统计报表页——顶部筛选条 + 概览卡片 + 各分区表。新增：

  • 顶部筛选条（与日志页同口径）：来源类型 / 接入协议 / 接入方式 / 域名关键字 / 时间区间。
  • 新增分区「来源与协议」：来源类型占比、接入协议占比、接入方式占比（占比卡 + 分组表，含次数、占比、平均耗时）。
  • 新增分区「Top 客户端来源」：按客户端 IP 聚合，展示次数、占比、平均耗时、主要来源路径，并附客户端归属（运营商 / 地域）标注。
  • 保留现有分区：来源路径分布、分流列表命中明细、Top 域名、按天趋势、结果与类型分布。

处理规则：

  • 全部分区受顶部筛选条件约束；筛选语义与日志页完全一致（同一口径，见 §4）。
  • 平均耗时一律剔除超时记录（耗时 ≥ 查询超时阈值），超时单独计入「超时」（沿用现状口径）。
  • 新增维度的占比分母 = 当前筛选窗口内的总查询数。

结果与状态变化：切换筛选后整页重新聚合；概览卡片展示总查询数、独立域名、平均耗时、超时与统计窗口（沿用现状）。

例外：

  • 统计窗口内无记录 → 空状态提示；日志被关闭时给出开启指引（沿用现状）。
  • 旧数据来源维度为空 → 计入「未知」分组，并在卡片附注说明，避免把历史数据误读为外网/内网。
  • 查询超时未配置 → 「超时」卡片显示「无法判定」（沿用现状）。

FR-3外网访问筛选（贯穿日志与统计）

目的：把线上外网（公网客户端）流量一键聚焦，是本次需求的核心增量。

触发：在解析日志页或统计报表页点击「外网访问」快捷按钮；或手动把「来源类型」置为「外网」。

处理规则：

  • 「外网访问」快捷筛选等价于设置来源类型 = 外网（即客户端 IP 为公网地址），并清空会与之冲突的接入方式选择。依据：以客户端 IP 是否为公网地址判定「外网」，可同时覆盖经公网入口接入与公网客户端直连的情形。
  • 快捷按钮在日志页与统计页语义一致：日志页据此刷新表格，统计页据此重新聚合。
  • 页面内切换（日志 ↔ 统计）时保持同一组来源筛选条件，避免两页结论不一致。

结果与状态变化：两页同时进入「外网访问」视图；筛选条高亮当前生效条件，便于随时还原。

例外：当前保留期内无外网记录 → 空状态提示「当前无外网（公网客户端）请求」。

口径 · 已确认

「外网访问」采用按来源类型（客户端 IP 为公网地址）的口径，会同时纳入「公网客户端直连 DoT」等非入口流量；如需只聚焦经公网入口（前置代理透传）的流量，可再叠加「接入方式 = 经代理」进一步收窄。

6共享规则与例外

以下规则被多个模块引用，在此统一规定；各功能小节只引用名称，不再重复定义。

规则内容
来源口径唯一来源类型 / 接入协议 / 接入方式 / 归一化客户端 IP 的定义见 §4；日志筛选与统计聚合必须使用同一口径。
筛选条件一致同一组来源筛选条件在解析日志页与统计报表页语义相同，且跨页保持。
客户端归一「客户端」一律展示为 IP（不带端口）；端口不作为筛选维度。
耗时口径平均耗时剔除超时记录；超时按「耗时 ≥ 查询超时阈值」判定并单独汇总。
保留与清理来源维度随记录一同写入、一同按现有保留策略（保留时长 + 条数上限）清理。
历史兼容缺失来源维度的旧记录一律归入「未知」，不参与「外网访问」筛选。
无副作用来源维度仅用于观测与筛选，不改变任何解析结果与分流决策。

统一例外清单

  • 客户端 IP 缺失 / 无法解析 → 来源类型「未知」。
  • CIDR 或 IP 输入非法 → 前端提示，不发起查询。
  • 无匹配结果 → 空状态 + 调整建议。
  • 日志记录被关闭 → 明确的关闭提示与开启指引。
  • 统计窗口内无数据 / 超时未配置 → 对应空状态与「无法判定」提示。
